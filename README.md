# Notion Agent Connector

Локальное окно чата, пул сохранённых сессий, OpenAI-совместимый текстовый API
и MCP-коннектор. Список чатов, история и сессия используют реальные запросы
к `app.notion.com/api/v3/`.

## Запуск

Нужны Python 3.10+ и requests:

```powershell
py -3 -m pip install -r requirements.txt
py -3 -X utf8 server.py
```

Откройте http://127.0.0.1:8765 или запустите `run.ps1` из папки клиента.
При старте сервер проверяет все сохранённые сессии чтением списка чатов.
Если сессии нет или Notion отвечает 401/403, интерфейс предлагает вставить cURL.
Сетевая ошибка отображается отдельно: можно повторить проверку без замены сессии.

## Откуда взять cURL для входа

1. Откройте https://app.notion.com в Chrome / Edge и войдите в аккаунт.
2. Выберите нужный workspace. Откройте DevTools: F12 или Ctrl + Shift + I.
3. На вкладке Network выберите Fetch/XHR. В фильтре введите
   `getInferenceTranscriptsForUser`.
4. В Notion AI откройте историю / список чатов. Если запроса нет,
   перезагрузите страницу с открытым Network и откройте историю снова.
5. У запроса `POST /api/v3/getInferenceTranscriptsForUser` со статусом 200
   выберите правой кнопкой Copy → Copy as cURL (bash).
   Обычный Copy as cURL или вариант cmd также поддерживаются.
6. Вставьте команду целиком в окно «Обновить сессию» и нажмите
   «Проверить и подключить». Запускать команду в терминале не нужно.

Также подходят `getInferenceTranscriptsUnreadCount` и
`syncRecordValuesSpaceInitial`, если есть cookies, user ID и space ID.
Запросы Google Translate и загрузки JS-файлов не подходят.

Парсер извлекает Cookie, user ID, space ID, версию клиента, User-Agent
и cell hint. Скопированный endpoint и его тело не исполняются:
кандидат проверяется отдельным запросом чтения списка чатов.
Только после успешной проверки профиль атомарно сохраняется на диске.
Неверный cURL не уничтожает рабочую сессию. «Добавить сессию» сохраняет ещё
один профиль, а «Обновить выбранную» обновляет его cookies.

Сессии и ключ коннектора хранятся вне исходников:
`%LOCALAPPDATA%\NotionAgentConnector\session.json`.
Через `--session путь.json` можно выбрать другой файл.
Cookies не передаются обратно в интерфейс и не печатаются в логах.
Старый файл с одной сессией автоматически переносится в формат пула,
с сохранением её credentials. Профили и приоритеты сохраняются между запусками.

## Работа с чатами

Откройте существующий чат слева. Клиент загружает `thread` и все его
`thread_message`, сохраняя порядок `thread.messages`.
Он показывает пользовательские сообщения, видимые ответы и краткий журнал
инструментов. Создавать новый чат пока следует в Notion — затем обновите список.

Отправка реконструирована по сохранённому коду фронтенда Notion:
`saveTransactionsFanout` → `runInferenceTranscript`.
Выбран поддерживаемый фронтендом режим полных шагов `asPatchResponse=false`.
Обычная отправка не повторяется при неизвестном исходе. При подтверждённом
лимите и включённом переключении контекст переносится в отдельный тред
резервного профиля. Обновите историю, чтобы увидеть результат.
Поток отображается постепенно, а после окончания история перечитывается из Notion.

Чтение и обновление сессии проверены живыми запросами. Генерация и ротация
проверены на подставном Notion backend, включая отказ по лимиту, частичный ответ
и неопределённый исход. Подтверждения успешного ответа на новое сообщение через
живой Notion пока нет: внутренний протокол может потребовать корректировки.

## Использование из Python

```python
from notion_client import NotionAgentClient

client = NotionAgentClient.from_file()
threads = client.list_threads()
history = client.load_thread(threads['threadIds'][0])

# Это отправляет новое сообщение в Notion:
for event in client.send_message(threads['threadIds'][0], 'Привет!'):
    if event['type'] == 'messages':
        print(event['messages'])
```

Проверки: `py -3 -X utf8 -m unittest discover -s tests -v`.

## Несколько сессий и приоритеты

1. Добавьте профили через «+ Добавить сессию», дав каждому понятное имя.
2. Для каждого профиля выберите нужный чат и нажмите «Выбрать как агента профиля».
   Его конфигурация используется для новых API-разговоров. Если в workspace
   всего один чат, он выбирается автоматически после проверки сессии.
3. В окне «Сессии и приоритеты» задайте порядок: 1 — первый, 2 — резервный и т.д.
4. «В автопуле» временно включает / исключает профиль из автоматического выбора.
5. В выпадающем списке слева можно вручную переключаться между сессиями.

Автоматическое переключение работает при HTTP 429 и известных машинных кодах
`rate_limited`, `credit_limit_reached`, `ai_credits_exhausted`, `quota_exceeded`,
`usage_limit_reached` до начала ответа или инструментов. Неподтверждённые ошибки
не распознаются по словам в тексте: мост возвращает ошибку вместо повторной мутации.
Каждый профиль пробуется максимум один раз на запрос.

`Retry-After` / известное время восстановления задаёт паузу. Если Notion не сообщил
время восстановления, профиль остаётся ограниченным до ручного «Повторить после
лимита». Проверка авторизации и обновление cookies не сбрасывают известный лимит.
Несколько профилей одного аккаунта и workspace считаются общим бюджетом при
машинном отказе по квоте кредитов. Обычный rate limit блокирует только отказавший
профиль: резервный агент может иметь другое ограничение. Отдельные cookies сами
по себе не создают дополнительную квоту.

История внешнего разговора передаётся резервному агенту текстом. При API-completion
создаётся отдельный тред, поэтому независимые запросы не используют чужую историю.
Для чат-окна при переключении также создаётся тред в резервном workspace; исходный
тред не удаляется. Исходная история не появляется в резервной сессии автоматически
при простом переключении выпадающего списка — только при явной отправке с failover.

## Подключение API

Нажмите «Подключение API / MCP». Окно показывает адреса, ключ и пример конфигурации.
По умолчанию сервер доступен только на этом компьютере. Передавать можно исходники
и примеры подключения; получатель импортирует собственные сессии.

| Интерфейс | Адрес |
|---|---|
| OpenAI-compatible Base URL | `http://127.0.0.1:8765/v1` |
| Список алиасов | `GET /v1/models` |
| Ответ / streaming | `POST /v1/chat/completions` |
| OpenAPI 3.1 | `http://127.0.0.1:8765/openapi.json` |
| MCP Streamable HTTP | `http://127.0.0.1:8765/mcp` |

API и MCP требуют `Authorization: Bearer <ключ коннектора>`.
Этот ключ открывает доступ к настроенным профилям через сервер, но не раскрывает
их cookies. Храните его у клиентов, которым нужен этот доступ.

`notion-auto` выбирает сессию по приоритету. Алиас
`notion-session-<id профиля>` закрепляет запрос за одной сессией и отключает failover.
Это алиасы маршрутизации, а не реальные имена моделей Notion: модель и агент берутся
из выбранного шаблонного чата каждого профиля.

Пример Python SDK, когда пакет `openai` установлен:

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url='http://127.0.0.1:8765/v1',
    api_key=os.environ['NOTION_CONNECTOR_KEY'],
    max_retries=0,
)
response = client.chat.completions.create(
    model='notion-auto',
    messages=[{'role': 'user', 'content': 'Привет!'}],
)
print(response.choices[0].message.content)
```

Текстовый мост поддерживает JSON и `stream=true` с SSE, текстовые сообщения
system/developer/user/assistant. Он не поддерживает `/v1/responses`, изображения,
OpenAI function/tool calls и настройку sampling через temperature / max_tokens.
Нетекстовые сообщения и определения инструментов отклоняются; прочие параметры
генерации не управляют конфигурацией агентной модели Notion.

Неизвестный исход уже начатого запроса возвращается как 409, чтобы клиент не
повторял потенциально принятую генерацию. Streaming-ошибка после частичного текста
передаётся как `error` в SSE, без успешного `[DONE]`. Cookies и token-величины
расхода не подставляются в ответы SDK.

## OpenCode и MCP

Для работы с локальными инструментами кодирующего агента подключайте Notion через
MCP к вашей основной модели. Notion-текстовый провайдер не исполняет инструменты
файловой системы OpenCode; инструментами в Notion управляет сам удалённый агент.

Пример подключения: `examples/opencode.json`. Вариант с новым ключом `providers`
и runtime-пакетом OpenCode v2: `examples/opencode-v2.json`.
Ключ берётся из окружения `NOTION_CONNECTOR_KEY`. Конфигурация в окне интерфейса
использует текущий порт сервера.

MCP предоставляет пять инструментов:

- `list_notion_sessions` — профили и состояния;
- `list_notion_threads` — список чатов;
- `read_notion_thread` — видимая история;
- `ask_notion_agent` — вопрос с автоматическим выбором сессии;
- `send_notion_message` — сообщение в конкретный тред без смены сессии.

`session_id` закрепляет инструмент за конкретным профилем.
Инструменты отправки создают сообщения в Notion; это отражено в их MCP annotations.
Статeless MCP принимает JSON-RPC через POST, отвечает JSON и принимает уведомления
с HTTP 202. GET-подписка на события не используется.

Для клиентов, принимающих только MCP stdio, используйте `mcp_stdio.py` и шаблон
`examples/mcp-stdio.json`. Замените `ABSOLUTE_PATH_TO_CONNECTOR` на путь к папке
и сначала запустите сервер. Адаптер берёт ключ из окружения или сохранённого файла
пула и пишет в stdout только JSON-RPC.

Конфигурации сверены с первичными источниками:
[OpenCode providers](https://opencode.ai/docs/providers/),
[OpenCode v2 providers](https://opencode.ai/v2/docs/providers),
[OpenCode MCP](https://opencode.ai/docs/mcp-servers/),
[MCP transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports),
[MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
